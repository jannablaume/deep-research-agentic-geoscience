- AI Agent for Reverse-Engineering Legacy Finite-Difference Code and Translating to Devito (2026, arXiv). [[arxiv:2601.18381]]
  Built for reverse engineering of legacy Fortran finite-difference programs and translation into Devito. Architecture `pipeline-with-agent`; techniques: retrieval; knowledge-graph; code-execution; self-reflection; planning; guardrails-validation. Base model: not stated for the code-generation model (described only as 'open-source Large Language Models' via a 'chat.ese LLM API'); GPT OSS 120B is named only as the G-Eval evaluator.
  Calls: a Neo4j Devito knowledge graph (12,793 nodes, 62,362 relationships, 70 Leiden communities) queried through four parallel retrieval mechanisms via Cypher; BGE-M3 embeddings; a Fortran static analyser (FortranCodeAnalyzer); LangGraph routing across eight workflow nodes; Pydantic schema enforcement; Ruff formatting; AST-based Python syntax validation and API-compliance linting; code execution for correctness checking; an LLM-as-judge G-Eval evaluator.
  Evaluated by two evaluations - a retrieval-quality protocol over eleven benchmark queries at three complexity tiers scored by Precision@5, Recall@5, MRR and response time against predefined ground-truth references, plus a code-translation assessment of 13 Devito finite-difference test cases combining five-dimensional static analysis with G-Eval LLM judging at equal weight. Baseline: comparison of four retrieval strategies (Fast, Comprehensive, Deep, Hybrid) against each other; vanilla LLM output without the RAG framework compared only qualitatively through error case studies; no baseline translation system. Data: synthetic.
  Reported: a Grade-A success rate of 76.9% across 13 test cases; retrieval at Precision@5 of 0.964 and Recall@5 of 0.930. Demonstrated maturity `M1` (claimed: the incorporation of feedback mechanisms motivated by reinforcement learning, enabling a transition from static code translation toward dynamic and adaptive analytical behavior).
  Authors' stated limitation: Authors state that although the system stores comprehensive conversion history, 'its capabilities for advanced data mining and pattern discovery remain limited'; that the quality evaluation framework relies on fixed predefined thresholds that cannot adjust to code type, complexity or historical performance, so adaptability 'is constrained by this static configuration'; and they concede the reported MRR 'look[s] too good' because each query has a set of valid references rather than a unique target, which 'limits the ability of MRR to differentiate retrieval quality under the current evaluation configuration'.

- **ESHM20-MCP.** An LLM-agent interface for end-to-end probabilistic seismic hazard and risk analysis (2026, npj Natural Hazards). [[doi:10.1038/s44304-026-00262-z]]
  Built for conversational end-to-end probabilistic seismic hazard and risk analysis over European reference models. Architecture `agent-plus-solver`; techniques: tool-calling; planning; memory; physics-solver-in-the-loop; guardrails-validation. Base model: Claude Sonnet 4.6; a locally served 7B model (clients named: Claude Code, Codex, VS Code).
  Calls: twenty-four typed MCP/JSON-RPC endpoints wrapping OpenQuake plus ESHM20/ESRM20 (compute hazard, compute uhs, compute cms, estimate loss); Nominatim geocoding; USGS Global VS30 Mosaic; ESM waveform retrieval.
  Evaluated by equation-level verification against analytic/tabulated oracles; hazard replication vs ESHM20/EFEHR at a 73-city European panel and two engineering return periods; supplementary tool-selection accuracy test with/without a skill description. Baseline: official ESHM20 values via the EFEHR hazard service (complete logic tree, 10,000 Monte-Carlo runs). Data: benchmark.
  Reported: replicated 475-year spectral accelerations match official/published values within a median of 5%, and within 28% at 97% of cities. Demonstrated maturity `M2` (claimed: a working tool for the European earthquake engineering community and a reusable template for agentic interfaces to validated scientific computing).
  Authors' stated limitation: Default branch subsets do not cover every authorized ESHM20 logic-tree branch; 20 km area-source discretisation and finite distance cutoffs; deterministic highest-weighted branches rather than full-tree Monte-Carlo (principal source of residual); some taxonomy strings lack ESRM20 vulnerability functions; topographic-slope VS30 proxy is uncertain at a single site; first-call hazard timings 37-488 s per site on one CPU core.

- **StripPool-UNet+FPN.** Consensus-gated Multi-Agent Neural Architecture Search for Seismic Fault Segmentation (2026, arXiv). [[doi:10.48550/arxiv.2608.13889]]
  Built for neural architecture search for seismic fault segmentation under a tight labelled-data and parameter budget. Architecture `multi-agent-flat`; techniques: multi-agent-debate; role-specialisation; code-execution; self-reflection; memory; guardrails-validation. Base model: Claude (Anthropic), GPT-5.1 (OpenAI) and Gemini 2.5 Pro (Google).
  Calls: code authoring and cross-review of complete PyTorch network implementations; an automated pre-training validator (AST parsing, instantiation, forward and backward pass at batch size 1 on three section shapes, spatial-dimension and 450,000-parameter checks); a train-and-score loop on a single laptop GPU via the MPS backend; a JSON search history, ban list and per-provider token logger.
  Evaluated by an identical-protocol benchmark retraining every architecture including all baselines on all 100 training sections for 60 epochs with the same loss and optimizer, evaluated on the full test volume, reporting F1, IoU, precision, recall and PR-AUC; during search, candidates were scored as the mean of three trials on a five-section proxy with keep-or-revert gating. Baseline: published-capacity U-Net (31.04M), U-Net (1.81M), DeepLabV3-ResNet50 (39.63M), Attention U-Net (1.83M), and a 1.49M-parameter reference baseline within the search lineage. Data: benchmark.
  Reported: the discovered network is 'simultaneously the smallest and the most accurate model: F1 0.578 and IoU 0.406 at 0.43M parameters', beating the published-capacity U-Net by +0.094 F1 at 73x fewer parameters. Demonstrated maturity `M2` (claimed: for specialized dense-prediction tasks, reasoned code-level architecture search is now cheaper than scaling, and multi-model debate is an effective quality gate for scarce training compute).
  Authors' stated limitation: Authors report a cautionary finding that 'optimizing recall alone silently discards the best F1 designs', noting an earlier recall-driven search 'had kept a worse model and reverted its genuinely best design'; they state quantitative metrics are often insufficient for fault segmentation given incomplete and uncertain ground-truth labels, so the pipeline can discard valid architectures on minor metric regressions, and propose a future agent to judge visual quality; they note published Thebe results are not directly comparable because they use tolerance-based OIS/ODS matching on different splits, and that one debate run was aborted on a provider transport failure.

- **TREMORS.** TREMORS: An Agentic Assistant for Multi-Datacenter Seismic Data Acquisition (2026, arXiv). [[doi:10.48550/arxiv.2609.01777]]
  Built for automated retrieval of seismic waveforms and metadata across multiple FDSN datacenters from natural-language queries. Architecture `agent-plus-database`; techniques: tool-calling; planning; task-decomposition; memory; guardrails-validation. Base model: gpt-oss:120b (run locally via Ollama).
  Calls: ObsPy API against FDSN web services (EARTHSCOPE, ORFEUS, GEOFON, SCEDC, NCEDC, IRIS, IRISPH5, USGS, ISC, EMSC, NRCAN, RASPISHAKE); fdsnws-dataselect waveform queries; LangChain/LangGraph execution nodes; Parquet/MiniSEED writers; a plotting and map-visualisation node.
  Evaluated by two illustrative example workflows (an event-based query over California 2021 M>6 events and a continuous-waveform query driven by a station file), traced node-by-node through the LangGraph decision tree; no metrics and no scored task set. Baseline: none. Data: not stated.
  Reported: not stated (no quantitative result is reported anywhere in the paper). Demonstrated maturity `M1` (claimed: an advancement in observational seismology for data acquisition and a blueprint for reproducible multi-step data procurement and analyses across multiple repositories).
  Authors' stated limitation: Authors state the agentic framework 'reduces uncertainty associated with natural-language interpretation' but 'does not eliminate it'; that semantic parsing may fail on ambiguous, imprecise or unusually phrased prompts; that correctness depends on the validity of the parsed schema and on embedded default parameter choices; that the system depends on external FDSN services and ObsPy interfaces and so is sensitive to heterogeneous metadata standards, incomplete station information, service outages and variability across datacenters; and that agents 'are not yet capable of replacing high-level subject matter experts or independently producing scientific discovery'.

- Automatic Knowledge Graph Construction and Query for Earthquake Catalogs (2026, arXiv). [[doi:10.48550/arxiv.2607.24984]]
  Built for schema-free construction of queryable knowledge graphs from raw earthquake catalog records to support natural-language querying. Architecture `agent-plus-database`; techniques: retrieval; knowledge-graph; guardrails-validation. Base model: gpt-4o-mini (entity and relationship extraction, community-report generation and answer synthesis; the authors note all results rely on this single model).
  Calls: Microsoft GraphRAG indexing pipeline; Leiden community detection; community-report generation; Global Search and Local Search retrieval over the graph; a rule-based reference knowledge graph (10,766 nodes, 113,620 edges) for ground truth; a vector-RAG baseline over the same chunks and embeddings; an LLM scoring assistant.
  Evaluated by a 100-question benchmark across five categories (summarisation, precise statistics, local retrieval, physical mechanism, temporal-stage comparison) run over three catalogs and two conditions before and after four prompt fixes, giving 1,200 GraphRAG answers plus 300 baseline answers, each scored 0-3 by an LLM assistant against catalog-derived statistics and a rule-based reference graph, with manual re-verification, a 29-answer blind audit and 95% bootstrap confidence intervals. Baseline: a vanilla vector-RAG pipeline sharing the same text chunks, embeddings, LLM and questions but no graph layer; plus a rule-based reference knowledge graph as a second ground truth. Data: real-field.
  Reported: four seismology-informed prompt fixes 'eliminate all targeted fabrications while sharply improving mechanism reasoning (up to 2.90/3)'; post-fix catalog-only overall averages of 1.69, 1.67 and 0.80 out of 3 for Qiaojia, Ridgecrest and Maduo. Demonstrated maturity `M3` (claimed: the first systematic demonstration of GraphRAG's schema-free construction capability transferring across independent earthquake catalogs at essentially zero ontology-engineering cost).
  Authors' stated limitation: Authors state precise-statistics queries remain weak across all conditions (0.50-1.04/3), attributing this to 'a fundamental structural flaw in retrieval-then-synthesize architectures when handling aggregate or ranking tasks' and recommending such questions be routed to deterministic database queries; that residual hallucinations persist after the fixes, including the true Ridgecrest M7.1 mainshock being misdated in 50-70% of relevant answers and an out-of-catalog Maduo mainshock presented as the catalog's own largest event in up to 60% of narrative-enriched answers; that per-catalog verification remains necessary before deployment, especially for well-known events; that narrative-text enrichment lowered scores for two of three catalogs and should be adopted only with per-catalog verification; and that because all results rely on a single model, hallucination rates and fix effectiveness might differ with another model.

- **TRACE.** TRACE: A Multi-Agent System for Autonomous Physical Reasoning for Seismology (2026, arXiv). [[doi:10.48550/arxiv.2603.21152]]
  Built for end-to-end construction of earthquake catalogs from continuous waveforms and mechanistic inference about the physics of earthquake sequences. Architecture `multi-agent-hierarchical`; techniques: tool-calling; code-execution; planning; task-decomposition; self-reflection; memory; retrieval; role-specialisation; human-in-the-loop; guardrails-validation. Base model: GPT-5 (primary backbone for all agents); Claude-4 and Gemini-3 evaluated as alternative backbones.
  Calls: ObsPy, SeisBench, DASPy, GaMMA, HypoDD, PhaseNet, EQcorrscan, SeismoStats, ETAS, xarray, cartopy, iris, eofs, scikit-learn; a library of over 2,200 specialised analytical modules; SCEDC and EIDA waveform archives; dynamic code synthesis and execution; online literature and API retrieval.
  Evaluated by a three-level benchmark of 76 atomic tasks, 32 multi-step workflow tasks and 2 integrated end-to-end research tasks, scored by RMSE and correlation against expert-designed reference solutions for deterministic outputs and by multi-reviewer structured expert scoring on a 1-5 scale for planning, code and synthesis; plus two full case studies (2019 Ridgecrest, 2025 Santorini-Kolumbo). Baseline: human experts, plus Claude-4 and Gemini-3 as alternative LLM backbones; also described as compared against manual interpretation and rule-based automated workflows. Data: real-field.
  Reported: the Ridgecrest workflow 'yielded over 90,000 precisely relocated earthquakes' from more than 1.59 million P- and 1.66 million S-wave arrivals; the benchmark scores themselves are presented only graphically and no numeric benchmark value appears in the text. Demonstrated maturity `M3` (claimed: advances the field from expert-dependent analysis toward knowledge-guided autonomous discovery in Earth sciences).
  Authors' stated limitation: Authors state the efficacy of TRACE 'remains intrinsically bounded by the fidelity of underlying physical models and the computational cost of high-fidelity simulations', and that its performance 'under extreme or data-sparse seismic events requires further validation through the integration of real-time observational streams and adaptive learning algorithms'; they describe a 'dual-ceiling effect' in which seismological tool precision sets the operational baseline while scientific rigour is capped by the reasoning depth of the underlying LLM.

- **SeisEvo.** SeisEvo: Evolution of Seismic Data Reconstruction Algorithms by Agents (2026, arXiv). [[doi:10.48550/arxiv.2608.18272]]
  Built for discovery of white-box seismic data reconstruction operators for trace interpolation and simultaneous interpolation and denoising. Architecture `multi-agent-flat`; techniques: code-execution; memory; guardrails-validation. Base model: not stated (the paper names only the Evolutionary Ensemble of Agents search backend and never identifies the underlying LLM).
  Calls: the EvE multi-agent coding backend; execution of candidate Python reconstruction programs; automated scoring on search-time sub-blocks (SNR, SSIM, MSE); programmatic legality gates; a candidate and failure pool used as search context.
  Evaluated by 20-round searches from each classical seed scored on 64x64x64 sub-blocks extracted from complete 3D volumes; the frozen operator was then validated once outside the loop on synthetic and field datasets not used during the search, with sweeps over missing ratios (30-70%) and noise scales (0.01-0.05). Baseline: classic POCS with exponential hard thresholding for interpolation; classic block-Hankel MSSA and the optimally damped rank-reduction method (ODRR) for interpolation plus denoising. Data: real-field.
  Reported: Evo-POCS improves SNR over classic POCS by 3.49 dB on average across missing ratios from 30% to 70%; Evo-MSSA reaches 10.70 dB, exceeding MSSA and ODRR by 7.15 and 3.31 dB respectively. Demonstrated maturity `M2` (claimed: the first reported application of LLM-driven constrained program evolution to the discovery of standalone seismic reconstruction operators).
  Authors' stated limitation: Authors state the discovered mechanisms 'are not conceptually new'; that the offline search cost is 'substantially more expensive than running a fixed hand-designed solver'; that the present evidence 'is restricted to seismic data reconstruction' and extension to denoising, deconvolution and inversion 'remains a hypothesis to be tested rather than a demonstrated capability'; that the seed and objective are fixed before each run and the effect of their choice 'has not been studied systematically'; that a single search trajectory per case cannot establish whether the budget is adequate; that the SNR and SSIM objectives require a complete reference so the protocol suits offline discovery only; and that for Evo-MSSA at low input SNR 'its error volume still contains coherent signal energy and random noise, indicating signal leakage and residual noise'.

- **Hydro-Agent.** Autonomous inverse modeling of complex groundwater systems via a physics-integrated large language model multi-agent framework (2026, Water Research). [[doi:10.1016/j.watres.2026.125886]]
  Built for autonomous inverse modeling/calibration of groundwater flow and multicomponent reactive-transport parameters via LLM-generated and self-debugged simulation code. Architecture `multi-agent-flat`; techniques: tool-calling; code-execution; planning; self-reflection; memory; role-specialisation; human-in-the-loop; simulator-in-the-loop; physics-solver-in-the-loop; guardrails-validation. Base model: DeepSeek-V3.
  Calls: MODFLOW-2005 groundwater flow simulator (via flopy); TOUGHREACT multicomponent reactive-transport solver; Python code execution; differential evolution, L-BFGS-B and TNC optimizers dynamically configured by the agent as it iterates.
  Evaluated by three case studies against ground truth: Case I synthetic steady-state flow (7-zone hydraulic conductivity field); Case II synthetic 1D reactive transport under 1/5/10% noise; Case III real-field 18-parameter calibration at the Aquia Aquifer, Maryland, against a baseline of the identical optimizer without LLM mediation. Baseline: directly coupled (non-LLM) optimizer; qualitative comparison to Dai and Samper (2006) GNLM and Chen et al. (2021) TNNA-AUS. Data: synthetic (Cases I-II); real-field (Case III).
  Reported: Case I RMSE 0.625 m to 0.0342 m; Case II final RMSE 1.296e-5/2.865e-5/5.630e-5 mol/L at 1/5/10% noise; Case III residuals driven below the 5e-5 precision threshold across 18 simultaneously calibrated parameters. Demonstrated maturity `M3` (claimed: operational capabilities analogous to a senior research engineer, autonomously formulating production-ready deployment protocols and rigorous error-handling mechanisms for real-time monitoring).
  Authors' stated limitation: the current implementation operates within a predefined conceptual model and does not independently revise stratigraphic interpretations, modify facies distributions, or adjust boundary conditions based on site-history information; the coupled hydrogeochemical models assumed spatially homogeneous reaction parameters and did not invert spatially distributed geochemical reaction fields; LLMs cannot yet substitute for the diagnostic capacity of a hydrogeologist in interpreting the mechanistic implications of modeling discrepancies.

  Built for translating plain-language user requests into automated multi-agent geophysical pipelines (ERT/seismic processing, time-lapse and structure-constrained inversion, petrophysical conversion) to estimate subsurface water content.   Calls: pyGIMLi; SimPEG; ResIPy; PyHydroGeophysX (the author's own package); HyRiver/PyDaymet for climate data; a Streamlit front-end (AQUAH).
  Evaluated by three retrospective real-field case studies on named US sites: direct water-content estimation at the No-Name Experimental Watershed, Wyoming; time-lapse inversion at the Mt. Demonstrated maturity `M3` (claimed: "GAGAW establishes a practical pattern for accessible, cross-modal geophysical analysis [...] from LLM-assisted scripting to LLM-orchestrated, tool-centric workflows").
  Authors' stated limitation: geophysics coverage is narrow (ERT, seismic refraction, basic climate linkage only); uncertainty quantification propagates only petrophysical parameter uncertainty, not survey/electrode/temperature-drift errors; LLM hallucination and malformed-JSON failures were documented during development.
